# ExtremeEditor Together — 時間区間先行の共同編集設計（重要・合意済み）

> **位置づけ:** 2026-10-16 の設計対話で合意した **目標仕様／設計原則**。
> 既存の floor-aligned PoC がこの仕様を満たしているという意味ではない。
> この文書は設計メモであり、このcommitで機能実装やテストのGREEN確認は行わない。

## 最重要結論

**曲からセグメントを作る → 担当者を割り当てる → 各自が空の区間に譜面を作る → 完成した内容を結合する。**

1. **セグメントの存在は、タイルの存在に依存しない。**
2. **セグメントは曲上の時間区間** `[StartSample, EndSampleExclusive)` を第一の識別基準として持つ。始点を含み、終点を含まない。
3. **譜面タイルはセグメントの内容物であり、後から追加できる。** タイルが1枚もなくても、担当者と時間範囲があれば有効な空セグメント。
4. **共同編集の分割点は、通常は曲の構成の境界**（イントロ、ビルドアップ、ドロップなど）に置く。床数の等分や既存タイルの位置からセグメントを作り始める設計ではない。
5. **編集者は時間グリッド上でセグメントの始点・終点を指定する。** 既存タイルへのスナップを必須にしない。

### 概念例

```text
曲: 0s                        40s                       80s                     120s
    |--------------------------|-------------------------|------------------------|
    Segment A [0,40)           Segment B [40,80)         Segment C [80,120)
    担当: A                    担当: B                   担当: C
    既存タイル: あり           既存タイル: 0枚          既存タイル: あり

    Bのセグメントは有効。Bはこの空の時間区間から新たに譜面を制作できる。
```

## 入力UI: osu!のようなBPM／オフセット由来のグリッド

- 楽曲を読み込み、**BPMと拍基準オフセット**から曲中時刻のグリッドを構成する。
- 波形、グリッド線、小節位置、曲の構成マーカー、セグメント境界、担当者をタイムライン上に表示する。
- 1/1、1/2、1/4、1/8、1/16などのスナップ間隔を切り替えて、時間境界をマウスで置けるようにする。
- 音楽上の正しい境界を選んだのにタイルがない場合でも、区間は空のまま作成する。**境界に合わせるために実タイルを勝手に作らない。**
- BPMが途中で変化する音源には複数のTiming Pointを扱う想定。一定BPMの場合の目安は `time(k) = beatOrigin + k * 60 / (BPM * subdivision)` 秒。
- 音楽のタイミンググリッドは**未完成のADOFAI譜面タイルから逆算して決めない**。譜面内部の `SetSpeed`・`Pause` 等から得られる床時刻と、音楽のグリッドは別の概念。
- 曲のオフセット、ADOFAIの `OffsetMilliseconds`、音源のデコード開始サンプル、ピッチ変更を同じ量として混同しない。プロジェクト内で単一の曲時間基準と換算規則を定義する。

## データモデル上の原則

```text
Song / Audio Timeline（唯一の時間基準、整数サンプル）
  ├─ Segment A: [startSample, endSample), owner A
  │    └─ ContentRevision: タイル・イベント等（あり）
  ├─ Segment B: [startSample, endSample), owner B
  │    └─ ContentRevision: 明示的な空の内容（合法）
  └─ Segment C: [startSample, endSample), owner C
       └─ ContentRevision: タイル・イベント等（あり）
```

- `SegmentTimeTimeline` に準じて時間区間と担当を保持し、区間の割り当て（ownership）と編集内容（content/revision）は別の責務とする。
- **空コンテンツは合法、読み込み失敗や欠損コンテンツはエラー**。空であることと存在しないことを混同しない。
- 有効な時間区間の重複は原則拒否する。未割当の隙間は、ワークフローに応じて許可・可視化する。Park済み内容は破棄しない。
- 割当境界を変えても、既存のタイルやイベントを勝手に時間移動・切り捨て・破棄しない。
- 編集セッションの最初に床データがなくても、曲の時間座標でカーソル・配置の基準を表現できるようにする。独立セグメントの向き・タイミング・結合部の状態（入口／出口）をどう確定するかは別途設計する。
- 時間区間は**サンプル単位の整数**で保持する（浮動小数点の秒を唯一の真実にしない）。

## タイル検索と二分探索: 成立条件を明示する

質問「この曲中時刻にタイルがあるか」について:

- 音楽時間に対するタイルの到達時刻を使って探索する。既存の床がある場合、`TimingMap` に `SetSpeed`、`Pause` 等を反映し、必要なら `PlaybackClock` により曲時間基準へ換算する。
- **二分探索を適用できるのは、検索対象の時刻列がその範囲内で単調に整列しており、検索を不連続にする未処理の区切りを含まないことを保証できる場合だけ。**
- 区切り・独立した編集領域がある場合は、先にその境界で範囲を分け、単調性の保証できる各範囲内で検索する。空の区間なら探索不要で「タイルなし」。
- `[a,b)` の中の既存タイルを `lower_bound(a)` ～ `lower_bound(b)` で取り出すのは、**その検索対象が時刻順に整列している場合だけ**。
- 複数の床が同じ曲時刻になる場合もあり得るので、`lower_bound` / `upper_bound` の等値の扱いを統一する。
- ただし **境界が存在するだけで数学的に二分探索が不可能になるわけではない**。全体の時刻列に単調性を保証できれば全体探索も可能。この保証なしに「譜面全体で常に二分探索可能」と決め打ちしない。

## 結合・完成譜面の制約

- 各セグメントは互いに独立して制作されるため、単に角度列を連結しても、曲中タイミング、BPM状態、惑星の向き、イベント効果が整合するとは限らない。
- 結合の前後で、時間上の割当、重複、未完成区間、接続部のタイミング・角度・持続イベント、編集権限を検査する。
- **完成譜面としてのExportは、未完成／空セグメントが残る場合や接続部の整合性が未確認の場合、黙って成功扱いしない。** 未完成プレビューの扱いは別途仕様決定。
- Gitの履歴マージと、ADOFAI譜面としての意味的な整合性検証は別。ファイル単位のGitマージ成功を譜面の完成と同一視しない。
- 完全な動作検証が未整備のクロスセグメント効果（`ScaleRadius`、`PositionTrack`、長時間 `MoveDecorations` など）は既存のfail-closed方針を維持する。
- 他者の作業や未Commit内容を暗黙のPull、Force Push、リセットなどで上書きしない。

## 次の開発順（合意済みの方向性、**着手前にRED設計**）

1. **Core RED**: 空の時間区間が、既存タイルゼロ枚でも有効な担当セグメントとして存在できること。欠損データと空コンテンツを区別し、既存内容は不変。
2. **Core GREEN**: 時間割当から独立した内容生成と編集コンテキスト（入口状態・曲時刻）を扱えるようにする。
3. **時間検索RED/GREEN**: 区切りのない単調な領域での二分探索、空領域、境界跨ぎ、同時刻床、BPM／Pause変更などを検証。
4. **UI RED/GREEN**: 波形＋BPM／オフセットのグリッド上で始点・終点を指定し、区間担当者を割当。既存床にスナップ強制しない。
5. **Semantic Merge／Export RED/GREEN**: 空・未完成・編集済みを区別し、結合時の時間／幾何／イベント整合性を安全に検証。
